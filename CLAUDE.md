# claude-mods

Claude Code mods, published as the `ame-mods` marketplace. Each mod lives in `mods/<name>/`.

## Done means green

A change is done when `pnpm lint`, `pnpm typecheck` and `pnpm test` all pass with no warnings. `pnpm lint` rewrites files, so run it before reading the final diff. Use pnpm for every install.

## Code style

Write every function as an arrow function assigned to a `const`. Biome enforces this with no auto-fix, so writing it that way first saves a lint round. Define a module-level arrow above any module-level code that calls it, since a `const` is not hoisted.

## Adding a mod

Load the `plugin-authoring` skill to build it. A mod built in a session lands in `~/.claude/dev-mods/<session id>/<name>/`, outside this repo; move it into `mods/<name>/`, then register it in three places:

1. `.claude-plugin/marketplace.json`, under `plugins`.
2. The mods table in the root `README.md`.
3. The `typecheck` and `test` scripts in `package.json`, which name each mod.

`mods/<name>/.claude-plugin/types/` is gitignored and generated by `plugin-authoring`; copy it from another mod when it is missing, or `tsc` cannot resolve `claude-code`.

## Changing a mod

- A change to behaviour bumps `version` in that mod's `.claude-plugin/plugin.json` and gets a test in `mods/<name>/tests/`, driven by `mock.clock` and a fake engine like the existing tests.
- Keep the mod's `README.md` (user guide) and `FLOW.md` (decision flow), where present, in step with the code.
- `cache-handoff` and `cache-keepalive` both time the same idle gap of the prompt cache. A change to either one's timing must account for the other: today `cache-handoff` still clears at 114 minutes even when `cache-keepalive` kept the cache warm.
